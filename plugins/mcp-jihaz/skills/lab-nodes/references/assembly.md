# Собрать СТЫКАМИ то, чего нет в реестре узлов

Открывать, когда узла под модуль нет и ты собрался класть детали `put`-ами по
своим координатам: ниша холодильника, портал, нестандартный короб, антресоль
чужой формы. Для того, что в реестре ЕСТЬ, читать нечего — зови узел.

## Зачем

Координата — то место, где ошибаются. Не правило, не размер, а именно `x`, `y`,
`z`, посчитанные в уме и записанные числом. Все четырнадцать узлов библиотеки
собраны НЕ так: у них объявлен **стык**, а координата и размер — его следствие.
Тот же слой открыт тебе целиком, и им строится то, чего в реестре ещё нет.

Разница в одной строке. Было:

```js
put({ name: 'полка', x: 16.5, y: 400, z: 0, l: 567, w: 490 });   // числа из головы
```

Стало — «полка стоит МЕЖДУ боковинами на полкодержателях», а 567 и 16.5
считает солвер:

```js
{ kind: 'inset', part: 'полка', fastener: 'shelf-support', pairs: [
  { face: 'l-', to: { part: 'боковина Л', face: 't+' } },
  { face: 'l+', to: { part: 'боковина П', face: 't-' } },
  { face: 't-', to: { envelope: 'y-' }, gap: -300 },
  { face: 'w-', to: { envelope: 'z-' } },
] }
```

**Числа 0.5 в рецепте нет.** Полка вышла 567 вместо 568, потому что зазор под
съём — свойство ЗАПИСИ ПОЛКОДЕРЖАТЕЛЯ, а не число, которое ты помнишь. Смени
крепёж на `confirmat` — полка станет 568 сама.

## Атом: деталь без места

Грани детали названы в ЕЁ СОБСТВЕННЫХ осях, и «верх», «перед», «лево» среди них
нет — они появляются только после постановки:

| Грань | Что это |
|---|---|
| `t-` / `t+` | пласти (по толщине) |
| `l-` / `l+` | торцы по ДЛИНЕ |
| `w-` / `w+` | торцы по ШИРИНЕ |

Куда какая ось смотрит в мире, решает `orientation` детали — та же карта, что у
`kit.worldSize`. Проверить, не гадая: `kit.faceAxis({orientation: 'vertical'},
'l-')` → `{axis: 'y', side: '-'}`.

У атома пишется **только то, что нельзя вывести**: `material` (толщина нужна
всегда) и `length`/`width` — если по этой оси всего одно совмещение. Написал
длину там, где её дают две грани, — солвер откажет `size-conflict` с обоими
числами. Это не придирка: ровно так в узлах жили константы `764` и `748`,
верные при корпусе 16 и врущие при 18.

## Стык: одна пара на ось даёт место, две — ещё и размер

```js
{ kind: 'inset', part: 'дно', fastener: 'confirmat', pairs: [
  { face: 'l-', to: { part: 'боковина Л', face: 't+' } },   // ← пара
  { face: 'l+', to: { part: 'боковина П', face: 't-' } },   // ← вторая: длина = следствие
  { face: 't-', to: { envelope: 'y-' } },
] }
```

Виды (`kind`) — имя для судьи и для человека, солверу хватает пар:

| Вид | Когда |
|---|---|
| `stack` | деталь стоит НА другой (торец в пласть снизу) |
| `butt` | торец в пласть сбоку |
| `inset` | вкладная между двумя (полка, дно навесного) |
| `gap` | контакта нет по замыслу: фасад, накладка, планка |
| `slide` | ящик на направляющих — `hardware: 'roller'` |
| `groove` / `rabbet` / `mitre` | **ОТКАЗ** с причиной, см. ниже |

`gap` в паре — это ЗАМЫСЕЛ («полка на 10 короче фронта»), число со знаком:
плюс наружу от грани габарита, минус внутрь. Зазор фурнитуры туда НЕ пишется —
он приходит из крепежа сам.

## Якорь — ГАБАРИТ, а не «первая деталь»

```js
envelope: { x: 600, y: 720, z: 500 },   // размеры модуля
origin:   { x: 0, y: 100, z: 0 },       // угол габарита: опора 100
```

Деталь, все грани которой совмещены с габаритом, и есть якорь — корень не
нужен, и ни у одного из четырнадцати узлов его нет. Нет ни корня, ни такой
детали — отказ `no-anchor`, а не молчаливый ноль в координатах.

## Крепёж — код из справочника, и он МЕНЯЕТ ГЕОМЕТРИЮ

`confirmat` · `minifix` · `dowel` · `shelf-support` · `'none'`.
Список живой: `kit.FASTENERS.map(f => f.id)`.

Не назвал крепёж вовсе — судья пишет «крепёж не назван»; написал `'none'` —
«собран без крепежа, так и объявлено». Это разные ответы, и второй законен:
фасад висит на петлях, задник прибивается, съёмная полка лежит.

## Три вызова, и все три обязательны

```js
const bad = kit.validateRecipe(recipe);      // имена по таблице, двусмысленность — отказ
const solved = kit.solveRecipe(recipe);      // {ok, panels, derived} | {ok:false, issues}
if (!solved.ok) throw new Error(solved.issues.map(i => `[${i.code}] ${i.message}`).join('\n'));
const { violations, notes } = kit.judgeBonds(recipe, solved.panels);
```

**Отказ солвера — отказ модуля.** Собранное «примерно» хуже несобранного: узлы
библиотеки бросают исключение и не отдают панели, делай так же.

`judgeBonds` отвечает на вопрос, которого физический судья не задаёт вовсе:
**не врёт ли модуль о себе.** `bond_declared_not_seated` — стык объявлен, а
геометрически его нет; это промах того, кто писал рецепт, а не расстановщика.
Ноты (`без крепежа`, `стык короче двух клеток 32`) нарушением НЕ считаются.
Короткий стык (царга 80) нотой БОЛЬШЕ НЕ БУДЕТ: на него встаёт одна единица
посередине, как в цехе.

Проверка независимым читателем — `kit.verifyBonds(recipe, panels)`: `detectJoints`
про рецепт не знает и ищет стыки по геометрии. Пустой список «не найдено» — два
разных пути к одному числу, а не сверка формулы с самой собой.

Присадка выводится из объявленного: `kit.bondFasteners(recipe, panels)` даёт
карту «стык → крепёж», `kit.bondFurniture(recipe, panels)` — готовые отверстия.

Это присадка ОДНОГО модуля, собранного рецептом. Крепёж ВСЕЙ СЦЕНЫ ставит
`kit.fasten(panels, { openings })`: он идёт по блокам, между модулями стыков не
видит, фасады и обвес пропускает с причиной и добавляет чашки под петли по
разметке открывания. Его вывод и уезжает в `report(panels, { furniture })`.

## Чего слой НЕ делает — и это ответы, а не «пока не сделано»

- **`groove` / `rabbet` — отказ: эталона в цехе нет.** Проверено: ни один из
  20 эталонов узлов не несёт ни одного реза, во всей библиотеке `2_Boxes` пазов
  под задник нет тоже. Задник либо накладной с отступом 1, либо вкладной между
  боковинами — и вкладной пишется обычной геометрией. Появится деталь,
  показывающая глубину, отступ оси и пласть, — вид включат.
- **`mitre`** — после эталона (подрезка обоих торцов).
- **Присадка под петли не выводится**: паспорт артикула расходится с
  измеренной геометрией по полям глубины, и петля не ложится в модель «торец в
  пласть» (чашка в фасад, ответная в ПЛАСТЬ боковины). Фасад объявляется `gap`
  + `'none'`.
- **Ящики TANDEM** — записи фурнитуры нет: в справочнике одна измеренная
  система `roller` (зазор 5, направляющая на 10 длиннее). Выдумывать зазоры
  TANDEM нельзя, они у каждой системы свои.

## Где рецепт НЕ нужен

**Одиночная деталь.** Столешница, цоколь, фальш-планка, полоса Gola — у них нет
ни одного стыка, и рецепт из одного атома это обёртка вокруг тех же трёх чисел.
Столешницу и цоколь кладёт `kit.row` (`countertop`, `plinth`, `filler`), полосу
профиля — `kit.nodes.golaStrip`.

**Модуль, у которого узел есть.** `describe_nodes` сначала, рецепт — только
когда в реестре пусто. Узел уже собран стыками и уже сверен с эталоном в
0.01 мм; переписывать его рецептом значит завести второй источник правды.

## Рабочий пример целиком

Ниша 600 × 720 × 500 на опоре 100: боковины во всю высоту, дно и крыша
вкладные, полка съёмная, задник ХДФ накладной с отступом 1.

```js
const CORP = { name: 'ЛДСП корпус KRONO_01', thickness: 16 };
const HDF  = { name: 'ХДФ большой формат', thickness: 4 };
const side = (part, face) => ({ kind: 'butt', part, fastener: 'confirmat', pairs: [
  { face, to: { envelope: face === 't-' ? 'x-' : 'x+' } },
  { face: 'l-', to: { envelope: 'y-' } }, { face: 'l+', to: { envelope: 'y+' } },
  { face: 'w-', to: { envelope: 'z-' } }, { face: 'w+', to: { envelope: 'z+' } },
] });
const between = (part, fastener, extra) => ({ kind: 'inset', part, fastener, pairs: [
  { face: 'l-', to: { part: 'боковина Л', face: 't+' } },
  { face: 'l+', to: { part: 'боковина П', face: 't-' } },
  { face: 'w-', to: { envelope: 'z-' } }, ...extra,
] });

const recipe = {
  name: 'Ниша',
  envelope: { x: 600, y: 720, z: 500 },
  origin: { x: 0, y: 100, z: 0 },
  atoms: [
    { name: 'боковина Л', orientation: 'vertical', material: CORP },
    { name: 'боковина П', orientation: 'vertical', material: CORP },
    { name: 'дно',        orientation: 'horizontal', material: CORP },
    { name: 'крыша',      orientation: 'horizontal', material: CORP },
    { name: 'полка',      orientation: 'horizontal', material: CORP, width: 490 },
    { name: 'задняя стенка', orientation: 'frontal', material: HDF },
  ],
  bonds: [
    side('боковина Л', 't-'),
    side('боковина П', 't+'),
    between('дно',   'confirmat', [{ face: 't-', to: { envelope: 'y-' } }, { face: 'w+', to: { envelope: 'z+' } }]),
    between('крыша', 'confirmat', [{ face: 't+', to: { envelope: 'y+' } }, { face: 'w+', to: { envelope: 'z+' } }]),
    between('полка', 'shelf-support', [{ face: 't-', to: { envelope: 'y-' }, gap: -300 }]),
    { kind: 'butt', part: 'задняя стенка', fastener: 'none', pairs: [
      { face: 't+', to: { envelope: 'z-' } },   // ← пласть задника В тыл габарита, сам он СНАРУЖИ
      { face: 'l-', to: { envelope: 'x-' }, gap: -1 }, { face: 'l+', to: { envelope: 'x+' }, gap: -1 },
      { face: 'w-', to: { envelope: 'y-' }, gap: -1 }, { face: 'w+', to: { envelope: 'y+' }, gap: -1 },
    ] },
  ],
};
```

Что из этого выходит (прогон в наборе, не пересказ):

```
боковина Л      720×500×16   at (0, 100, 0)
боковина П      720×500×16   at (584, 100, 0)
дно             568×500×16   at (16, 100, 0)
крыша           568×500×16   at (16, 804, 0)
полка           567×490×16   at (16.5, 400, 0)   ← 0.5 от полкодержателя
задняя стенка   598×718×4    at (1, 101, -4)  ← накладной: ЗА корпусом, а не в нём
judgeBonds: нарушений нет; нота — «стык 6 (butt) «задняя стенка»: собран без крепежа — так и объявлено»
verifyBonds: не найденных стыков нет
судья: нарушений нет
```

**Накладная деталь ложится СВОЕЙ ДАЛЬНЕЙ ПЛАСТЬЮ на грань габарита.** Тыл здесь
`z-` (ярусные узлы смотрят в +z), поэтому задник объявлен `t+` и встаёт в
z −4…0 — за корпусом. Напишешь `t-` — та же пласть сядет на z 0, и задник
окажется ВНУТРИ короба: `solveRecipe` соберёт, `judgeBonds` промолчит (стык
объявлен и он есть), а физический судья даст пять пересечений — с обеими
боковинами, дном, крышей и полкой. Слой сборки судит РЕЦЕПТ, тела проверяет
судья; поэтому смотреть надо на оба ответа, а не на один.

Ни одного из чисел 720, 568, 567, 584, 16.5 в рецепте нет. Поменяй
`corpusT` на 18 или высоту на 900 — они пересчитаются сами, и это ровно то, чего
не умеет `put` координатами.

## Собранное рецептом — всё ещё «руками»

`provenance` считает по метке узла, а её ставит РЕЕСТР. Модуль, собранный
рецептом мимо реестра, попадёт в `byHand` — это честно: узла под него нет.
Если модуль повторяется, это повод сказать технологу «заведите узел», а не
копировать рецепт из заказа в заказ.
