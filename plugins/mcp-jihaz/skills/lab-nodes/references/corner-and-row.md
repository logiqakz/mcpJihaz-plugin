# Угловой и ряд: по именам стен, без координат

Открывать, когда узлы выбраны и надо расставить их вдоль стен. Оси и `kit.place`
— в `axes-and-placement.md`.

## Угол — только `kit.corner`, по именам стен

Угол в этом цехе — **два прямых короба со стыковочными планками**, а не
Г-образный угловой (эталон технолога 07.09.2026, `models/lab/nodes/ugol-*`).
ГЛУХОЙ короб (`cornerBlind` внизу, `topBlind` вверху: фальшь у стены угла,
глухой фасад, дверца) встаёт вдоль ПЕРВОЙ стены тылом к ней; СТЫКОВОЧНЫЙ
(`bottomJoint` — обычный короб с планками 40 и 100; `topJoint` — с блендой и
панелями стыковки) — вдоль ВТОРОЙ, планками к лицевой плоскости фасада
глухого. Угловых Г-образных узлов (`cornerSink`, `cornerStorage`, `topCorner`)
больше нет — их эталоны сняты.

```js
const wallA = panels.filter((p) => p.name.startsWith('Стена A'));
const wallB = panels.filter((p) => p.name.startsWith('Стена B'));
const corner = kit.corner({
  between: [wallA, wallB], tier: 'bottom',
  blind: { width: 950, corpusT: 16, facadeT: 18 },   // opts cornerBlind / topBlind, side выберут стены
  joint: { width: 368.81 },                          // opts bottomJoint / topJoint, joint выберут стены
  name: 'Угол',
});
panels.push(...corner);                              // все панели угла
// corner.blind — глухой, corner.joint — стыковочный: от них идут ряды
```

Поворот, стороны и `at` выводятся из панелей стен: `rotate` не задаётся,
`side` и `kind` не принимаются. Тыл КОРПУСОВ от стен — `setback`: 50 внизу
(правило 6; задник стыковочного 4 мм лежит в этом зазоре), 4 вверху (задник
вплотную к стене). Фальшь глухого кончается там, где начинается корпус
стыковочного; крайняя точка стыковочного в сторону глухого лежит НА лицевой
плоскости его фасада (`jointGap` 0). Поменять стены местами — глухой в другом
ряду; это выбор состава, а не геометрии.

Параллельные стены, стены не сходящиеся в угол, пустой список — отказ с
причиной, а не «примерно в угол». `place(cornerBlind, {rotate})` руками для
угла не пишется: ровно там угол «Баура» и «Auez» ставили мимо, а таблицу осей
человек проверял `assert`-ами.

## Сначала ТЗ, потом ряды: `kit.validateSceneSpec`

Прежде чем писать ряды, опиши согласованное ТЗ спекой и проверь её.
`kit.validateSceneSpec(спека)` отвечает списком ошибок БЕЗ постройки,
`kit.buildScene(спека, panels)` строит по ней, `kit.targetsFromSpec(спека)`
отдаёт цели судье. Спека — дерево состава плюс три вещи, без которых оно не
сцена: `along` (вдоль какой стены ряд), `from` (от чего он идёт) и `rest` (чем
закрыт остаток участка). Координат в ней нет — их считает солвер.

Она ловит ровно то, что иначе выясняется отказом на середине: `from`, равный
`along`; ряд над рядом без столешницы; ряд, не добирающий до конца участка
(«не добирает 450 мм до 4150») — тот самый промах, когда узел отказал, а
модуль молча ужали. `width` у модуля — ХОД ПО РЯДУ и цель ТЗ; параметры узла
живут в `opts`. `facades` — тоже цель, а не опция.

## Ряд — только `kit.row`, от угла или от стены

```js
const lower = kit.row({
  along: wallA, from: corner.blind, namePrefix: 'Низ',   // от торца глухого
  countertop: { thickness: 38 },         // ОБЯЗАТЕЛЬНА, если сверху будет ряд с backsplash
  modules: [
    { node: 'bottomDrawers', width: 600, facadeHeights: [180, 180, 360] },
    { node: 'bottomBox', width: 600, facades: 1 },
    { node: 'bottomSink', width: 800 },
  ],
});
panels.push(...lower.panels);            // lower.end — где кончился ряд
const upper = kit.row({
  along: wallA, from: wallB,
  on: { row: lower, backsplash: 600 },   // низ выводится, а не считается в уме
  modules: [{ node: 'topBox', width: 600 }],   // только навесные: topBox, hoodBox, antresol
});
```

Две ошибки, на которых этот пример уже ломали (кухня «Bauer», 19.09.2026), и
обе — в нём самом, а не в наборе. **Фартук меряется ОТ СТОЛЕШНИЦЫ**: нижний
ряд без `countertop` не даёт `on.backsplash` точки отсчёта, и ряд отказывает
(«фартук бывает НАД СТОЛЕШНИЦЕЙ, а под этим рядом её нет»). До 19.09.2026
`countertop` стоял только в примере обвеса ниже, и скопировавший ЭТОТ пример
получал отказ на ровном месте. **В `on`-ряд идут только навесные узлы** —
`topBox`, `hoodBox`, `antresol`. `shelving` это НАПОЛЬНЫЙ стеллаж 2572 мм: он
несёт опору 100 внутри себя и на столешницу не ставится. Открытый верхний
короб — `topBox` с `facades: 0`, а не стеллаж, выбранный по слову «открытый».

`along` — стена панелями, `from` — от чего ряд идёт: стена угла (ряд от её
грани) или угловой узел / соседний ряд (от его торца). Направление — от `from`
к середине стены, поворот узлов к стене, тыл на `setback` (50 у напольных по
правилу 6, 0 у навесных — иначе судья скажет «висит в воздухе») — всё это
считает набор; координат у модулей нет. Ряд длиннее стены — отказ с числом.

## Обвес ряда — тоже `kit.row`, а не панельками

```js
const lower = kit.row({
  along: wallA, from: corner.blind, namePrefix: 'Низ',
  countertop: { thickness: 38 },   // толщину свод НЕ называет — она твоя
  plinth: { recess: 50 },          // утопление цоколя свод НЕ называет — тоже
  filler: 'toWall',                // остаток до стены закрыть планкой
  modules: [/* … */],
});
lower.trim; // { countertop, plinth, filler } — имена, габариты, место в мире
```

Столешницу, цоколь и фальшь на обрыве ряда руками больше не кладут: именно там
координаты считались заново и именно там промахивались. Числа берутся из свода:
свес **50 за фронт КОРПУСА** (правило 6; за фасад плита выходит меньше — он
живёт в свесе), цоколь **100** (правило 4, опора), планка в **плоскости
фасадов** (правило 30), низом **по низу дна** (правило 31), высотой **по
обрывающемуся ряду** (правило 33), шириной не уже **30** (правило 29) и не шире
названных сводом **200** (правило 15) — остаток больше это недостающий модуль, и
`kit.row` так и отвечает.

Чего в своде НЕТ — то он спрашивает, а не выдумывает: `countertop: true`
отвечает «свод не называет толщину столешницы (38/16/40/28)», `plinth: true` —
«свод не называет утопление цоколя». Подставить «обычные» числа за тебя он не
может: они уедут в раскрой молча. У навесного ряда столешницы и цоколя нет
вовсе (отказ), фальшь — есть.

Чего в ряду по-прежнему НЕТ и что идёт в `assumptions`: вырезы под мойку и
варочную, стык Г-образных столешниц (правило 9), планки под потолок, накладка
на открытый торец (правила 25–28 — там своя глубина «по видимости»).

## Вертикаль кухни — `on`, а не `y` в уме

```
пол → опора 100 → нижняя база → столешница → ФАРТУК → верхняя база → антресоль → планка → потолок
```

Сумма этих слоёв и есть высота кухни, значит низ навесного ряда — СЛЕДСТВИЕ, а
не координата. `on: { row: нижнийРяд, backsplash: 600 }` берёт верх столешницы
с построенной плиты и прибавляет фартук; `upper.y` — что получилось. Антресоль
над навесным — `on: { row: верхнийРяд }` БЕЗ фартука: коробы стоят друг на
друге (правило 14), и `backsplash` там отказ, а не ноль.

Высоту фартука свод не называет нигде — `kit.row` её спрашивает, как толщину
столешницы и утопление цоколя. Напольный узел с `on` — отказ: он несёт опору
100 внутри себя и на столешницу не ставится.

`y` числом принимается по-прежнему и побеждает вывод, но расхождение уходит в
`decisions` обоими числами: «низ ряда y = 1458 … ПЕРЕОПРЕДЕЛЕНО числом: y =
1500, расхождение с выводом 42 мм». Молча ошибиться на вертикали больше нельзя.

## Решения постановки — в ответе, числом

`kit.corner` и `kit.row` решают за агента поворот, зеркало, отступ от стены и
место каждого модуля. Всё решённое ответ постройки возвращает списком
`decisions`:

```
kit.corner «Угол» (напольный): глухой вдоль стены z− (грань 0), фальшью в стену x− (грань 0),
  поворот 0°, сторона left; занимает x 50..1000, z 50..583.19, высота до 820.
  Стыковочный вдоль стены x− (грань 0), поворот 90°, планками к глухому; занимает
  x 46..566, z 583.19..992 … Ряды продолжать: вдоль первой стены от глухого (from: угол.blind) …
kit.row «А1» (bottomBox): x 1000..1600 (ширина 600), тыл от стены 50, поворот 0°.
kit.row вдоль стены z− (грань 0): 1 мод., x 1000..1600, до конца стены (3000)
  остаётся 1400 мм — пусто: планка, модуль или допущение в assumptions.
```

Остаток до конца стены набор НЕ растягивает на модули (так делает чужой
генератор: «600 → 650, widened to the wall length», и размер, названный
человеком, уезжает молча). Остаток — решение агента: планка, ещё модуль или
честное допущение. **Читать `decisions` ДО вердикта**: ошибка постановки видна
там раньше, чем судья скажет «фасад в стену».
**Глубина и высота угла — параметры узлов**, и умолчания у глухого и у
ярусных узлов РАЗНЫЕ: `cornerBlind` по эталону технолога 950×720×533.19
(корпус 517.19 + фасад), `bottomBox` — 600×720×520. Ряд от глухого с
умолчаниями выйдет фронтом на 13 мм короче его фасадной плоскости, и
**`kit.row` сверяется с тем, от чего идёт, и ОТКАЗЫВАЕТ числами**:

```
kit.row: ряд фронтом 570 от стены, а «Угол глухой» — 583.19: 13 мм мимо.
```

Правильного умолчания тут нет: обмер настоящих заказов даёт 780 у «Достык»,
790 у Desarhome, 795 у «Меруерт» и 720 у библиотечного короба. Поэтому
**`kit.row` сверяется с тем, от чего идёт, и ОТКАЗЫВАЕТ числами**:

```
kit.row: ряд верхом 820, а «Угловой», от которого он идёт, — 880: ступенька 60 мм.
kit.row: ряд фронтом 570 от стены, а «Угловой» — 606: 36 мм мимо.
```

Сравнять можно с любой стороны — `depth` глухому (`blind: { depth: 520 }`) или
те же поля модулям ряда; выбирает высоту кухни человек, а не набор. Сравнение идёт только
когда есть с чем: от СТЕНЫ ряд стартует молча (у стены нет ни верха короба, ни
фронта), и ряд НА ДРУГОМ ЯРУСЕ (навесной над напольным) тоже — там разные верх
и глубина по замыслу.
