# Покупная фурнитура в изделии: найти, посмотреть, поставить

Открывать, когда в изделии есть то, что цех не делает, а ПОКУПАЕТ: сушилка,
карго, корзина, навес шкафа, опора, направляющая, лифт, ручка. Это ТОВАР
поставщика, и главное правило здесь одно:

> **Покупная единица не строится панельками. Её находят в каталоге компании и
> ставят целиком.**

Нарисованная «примерно такая» сушилка — это деталь, которую цех попытается
раскроить, и артикул, которого никто не закажет. В каталоге компании
**48 812 карточек**; у них есть имя поставщика, артикул, габарит, присадка и
(у части) настоящее тело, снятое из файлов Базиса и OBJ поставщика.

Крепёж (конфирмат, минификс, петля) — НЕ отсюда: он ставится `kit.fasten`, см.
`rules/tools.md`.

## Порядок — три шага, и ни один не пропускается

### 1. Найти словами — `search_furniture`

```
search_furniture({ ask: '…', text: 'направляющая KRS04' })
```

Отдаёт СПИСОК: имя, артикул, категория, поставщик, габарит в мм, число
отверстий, есть ли тело. Присадки и тела в списке нет намеренно — карточка с
тремя сотнями отверстий весит 48 КБ, и три таких подряд топят сессию.

Три вещи, на которых поиск ошибается, если о них не знать:

- **имена — как их написал поставщик**, а не как принято в цеху («Секция 01,
  NL 500», «KRS04/3 Направляющая»); ищи словом из имени, а не ролью детали;
- **категория пуста у трети карточек, артикул — у пятой части, тело есть
  меньше чем у половины**. Фильтровать этим вслепую значит терять товар;
  `with_body: true` ставить тогда, когда единицу надо ПОКАЗАТЬ на кадре;
- **поле `selector`** говорит, каким словом сервер сузил выдачу. У четверти
  каталога узкого слова нет вовсе — каждое стоит у пятисот и более соседей, — и
  тогда выдача почти случайна. Это сказано прямо; лечится другим словом в
  запросе, а не перебором страниц.

### 2. Посмотреть — `get_furniture`

```
get_furniture({ ask: '…', id: '001f84fd91_F184900889' })
```

Отдаёт одну карточку целиком — габарит, присадку — и **ПРЕВЬЮ КАРТИНКОЙ,
нарисованное самим Базисом**. Смотреть обязательно: по имени сушилку от карго
не отличить, а на картинке видно. Поставил, не посмотрев, — поставил не то.

Координаты присадки и коробки здесь — **в СВОИХ осях карточки**: единица
никуда не поставлена, и ноль у неё там, куда его положил чертёжник поставщика.

**Тела (меша) не отдаёт ни один из двух тулов, и просить его не надо**: у
навеса это 66 КБ координат, у сшитого из OBJ — под полмегабайта. Тело остаётся
на сервере; ты увидишь результат на кадре.

### 3. Поставить — `library` + `kit.mount`

Id карточек перечисляются в параметре `library` у `run_lab_script`; сервер
поднимает их вместе с телами и кладёт ПОЛЕМ `library` в набор — карточка
достаётся по id (`const { library } = kit`). Скрипт исполняется без сети —
подтянуть карточку по ходу ему нечем, поэтому список ЯВНЫЙ. Не перечислил —
поле пустое, и ставить нечего.

## Рабочий пример (числа — вывод этого самого кода)

Карточка настоящая: `001f84fd91_F184900889`, «KRS04/3 Направляющая» (BOYARD,
направляющая сушки в нижнюю базу). Её коробка в своих осях идёт
x 35…438, y −52…9, z 0…49.5, присадка — четыре отверстия ⌀6 × 2.

```js
// run_lab_script({ library: ['001f84fd91_F184900889'], script: … })
const короб = kit.nodes.bottomBox({ name: 'Н1', width: 600 });

const { library } = kit;                       // карточки, поднятые сервером
const KRS04 = library['001f84fd91_F184900889'];
const левая  = kit.mount(KRS04, { at: { x: 50, y: 120, z: 60 },
                                  name: 'Н1: направляющая KRS04 левая' });
const правая = kit.mount(KRS04, { at: { x: 50, y: 120, z: 60 }, mirror: 'x',
                                  name: 'Н1: направляющая KRS04 правая' });

report(короб, { furniture: [левая, правая] });
```

Что выдаёт постановка:

| | габарит в сцене | минимальный угол | первое отверстие |
|---|---|---|---|
| `{at}` | 403 × 61 × 49.5 | (50, 120, 60) | (57, 172, 60) |
| `{at, mirror: 'x'}` | 403 × 61 × 49.5 | (50, 120, 60) | (446, 172, 60) |
| `{at, rotate: 90}` | 49.5 × 61 × 403 | (50, 120, 60) | (50, 172, 456) |

Читается это так:

- **`at` — минимальный угол коробки, по всем трём осям.** У карточки ноль
  лежит в стороне от тела (x с 35, y с −52), и «поставить значит прибавить
  `at`» дало бы угол (85, 68, 60) — единицу на 35 мм правее и на 52 мм ниже,
  чем просили. У `kit.place` `at.y` ПРИБАВЛЯЕТСЯ, и это верно там: у панели
  узла своя абсолютная высота. Здесь прибавлять не к чему;
- **зеркало и поворот коробку от `at` не отрывают** — меняется то, что внутри:
  первое отверстие уезжает с 57 на 446 (зеркало) или с оси X на ось Z
  (поворот, вместе с направлением сверления). Поэтому проверять постановку
  надо по ПРИСАДКЕ, а не по тому, что коробка встала на место;
- **у каждой постановки свой id** (`…@1`, `…@2`): четыре одинаковые опоры —
  четыре разные единицы, а не одна, положенная четырежды.

Свод для закупа — по паре «карточка + имя»:

```js
kit.furniturePurchase([левая, правая])
// [{name: 'Н1: направляющая KRS04 левая',  article: null, count: 1, libraryId: '001f84fd91_F184900889'},
//  {name: 'Н1: направляющая KRS04 правая', article: null, count: 1, libraryId: '001f84fd91_F184900889'}]
```

Одно имя на две постановки даёт ОДНУ строку со счётом:
`[{name: 'Н1: направляющая KRS04', article: null, count: 2, …}]`. Артикул у
этой карточки в каталоге пуст, и в своде он `null` — не выдуман.

## Чего делать нельзя

- **Не рисовать покупную единицу деталями.** Сушилка из панелей уедет в
  раскрой, а артикул — никуда.
- **Не ставить, не посмотрев на превью.** Имя не описывает вид.
- **Не забывать `report(panels, { furniture })`.** Не отдал — единицы не
  будет ни в файле модели, ни у судьи, ни на кадре: она просто исчезнет, и
  никто об этом не скажет.
- **Не полагаться на судью.** Он судит только ПРИСАДКУ единицы; её габарит в
  проверки не входит вовсе — «сушилка шире короба», «опора не под дном»,
  «направляющая в чужом модуле» НЕ проверены, и вердикт говорит это нотой.
  Причина названа: фурнитура пересекает деталь законно и постоянно (чашка
  петли утоплена в фасад, направляющая привинчена к боковине), а обмера
  настоящих заказов не делали. Значит **смотри на кадр**: единица нарисована
  сиреневым и штрихом, а `snapshot.views[].hardware` говорит, что нарисовано
  телом, что коробкой и что пропущено с причиной. Крепёж с одной присадкой на
  кадре не рисуется намеренно.
- **Не считать, что единица заказана.** `purchase` в ответе постройки — это
  СВОД «что стоит в модели», а не строка закупа. В закуп её заводит отдельный
  явный шаг (`upsert_purchasing_lines`), и это решение владельца. Отчитываясь
  человеку, так и говори: единица в модели есть, в закуп не отправлена.
- **Не молчать о том, что не поднялось.** `library_notes` называет карточки,
  которых нет, тела, которые не прочитались, и перебор потолка (40 карточек и
  24 МБ тел на постройку). Единица тогда встанет коробкой или не встанет
  вовсе — это надо сказать, а не обнаружить на кадре.
